## Bug Fixes

### Hardening
- A `X-Vault-Token` now counts as configured authentication on every scope (KMIP, `/v1/crypto`, `/tokenize`, MS-DKE, KV, SSH): with `vault_api_enabled = true` and `vault_auth_verifier_url` as the only authentication method, a request without credentials is rejected instead of running as the default user ([#1437](https://github.com/Cosmian/kms/issues/1437)). Client action: send `X-Vault-Token` or authenticate another way, for example an mTLS client certificate whose CN is `default_username` for `ckms` provisioning
- Apply the server `key_encryption_key` to every object-creation path: derived keys, split-key shares, joined keys, key pairs generated by `Certify` and KV secret versions are now stored wrapped, like other keys. Wrapping accepts split-key shares; `Get`/`Export` of a share honours `key_wrap_type = NotWrapped` ([#1437](https://github.com/Cosmian/kms/issues/1437))
- Downgrade: with `key_encryption_key` configured, split-key shares created by this release are stored wrapped; earlier releases cannot join them (`JoinSplitKey` and Crypto Officer ceremony activation fail). Join or re-split them before downgrading

## Testing

- The SPIRE test tasks connect to the server with an mTLS `admin` client certificate (new `test_data/spire/certs/admin.crt`), because the Vault-token-only SPIRE server now rejects requests without credentials
