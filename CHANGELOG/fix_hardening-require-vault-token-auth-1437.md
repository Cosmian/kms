## Bug Fixes

### Hardening
- A `X-Vault-Token` now counts as configured authentication on every scope (KMIP, `/v1/crypto`, `/tokenize`, MS-DKE, KV, SSH): with `vault_api_enabled = true` and `vault_auth_verifier_url` as the only authentication method, a request without credentials is rejected instead of running as the default user ([#1437](https://github.com/Cosmian/kms/issues/1437))
- Apply the server `key_encryption_key` to every object-creation path: derived keys, split-key shares, joined keys, key pairs generated by `Certify` and KV secret versions are now stored wrapped, like other keys. Wrapping accepts split-key shares
- `Get` no longer implies other operations on a key: `Encrypt`, `Decrypt`, `Sign`, `MAC`, `DeriveKey` and the wrapping of a key with it (`Encrypt`) or its unwrapping (`Decrypt`) each require their own grant or ownership. `Get` and `Export` remain equivalent. Client action: grant the operation a user needs (for example `encrypt`) instead of relying on a `get` grant. A caller without the needed grant gets `Object_Not_Found`

### Documentation
- Replace "The `Get` super-privilege" in the authorization guide with the per-operation rules

## Testing

- The SPIRE test tasks connect to the server with an mTLS `admin` client certificate (new `test_data/spire/certs/admin.crt`), because the Vault-token-only SPIRE server now rejects requests without credentials
