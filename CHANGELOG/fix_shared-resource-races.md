## Bug Fixes

### API
- `GET /access/obtained` (`ckms access-rights list-obtained` / "access rights obtained" listing) now includes permissions granted to the wildcard user `*`, consistent with how per-object permission checks already treat wildcard grants as inherited by every user. Previously, an operation granted only to `*` (e.g. `grant_access(..., "*", ["get"])`) was silently omitted from a specific user's obtained-access-rights listing across all database backends (SQLite, PostgreSQL, MySQL, Redis-findex). Objects owned by the requesting user are still excluded from their own "obtained" listing, since ownership already grants full implicit access.

### Database
- Fixed an intermittent `Error: Database(SqlError("Error(\"database is locked\")"))` failure under `cargo nextest run --workspace --lib --features non-fips`, most visibly on `tests::security_regression::test_sign_preserves_kek_wrapping_with_usage_limits` and similar tests that close and reopen a SQLite-backed `KMS` instance on the same database file within a single test. The underlying `tokio_rusqlite::Connection` only closes its SQLite handle asynchronously (no synchronous `Drop`), so a new pool could attempt to open/migrate the same file before the previous connection had actually released it — a race that nextest's per-test-process parallelism made far more likely to trigger than under `cargo test`. `SqlitePool::instantiate()` (connection open, schema bootstrap, and column/activation migrations) and `set_parameter`/`set_db_state`/`set_current_db_version` now retry transiently "database is locked" / "database table is locked" errors with a capped exponential backoff (20ms–250ms, 5s budget) instead of failing immediately.

## Testing

### CLI test helpers
- Fixed a `cargo nextest`-only flakiness where `ckms` CLI tests could intermittently fail with `panicked ... called \`Result::unwrap()\` on an \`Err\` value: Os { code: 2, kind: NotFound, ... }` when spawning the `ckms` binary. The test-only auto-build helper (`ensure_ckms_binary`) used a process-local `std::sync::Once` to avoid rebuilding the binary more than once — which works under `cargo test` (all tests share one process) but not under `cargo nextest`, which runs every test in its own OS process: dozens of `ckms` test processes could race to invoke `cargo build --bin ckms` concurrently, each blind to the others already building or having just finished, occasionally observing the binary mid-relink. Replaced the single-process guard with a cross-process, atomically-created lock file so only the first process across the whole run performs the build; every other process simply waits for the binary to appear. This also removes dozens of redundant `cargo build` subprocess spawns that were previously issued (harmlessly but wastefully) by every `ckms` test process under nextest.

### Tooling
- `mise test` (the bare `.mise/tasks/test/_default` aggregator) now runs every test group under `.mise/tasks/test/` instead of only a curated subset (sqlite, psql, redis, helm, wasm, hsm, ui). Groups whose required infrastructure, credentials, or tools are unavailable locally (Docker, `nix-shell`, `kubectl`/`helm`/`minikube` + a reachable cluster, cloud/service credentials, the `authentication` submodule, an OTLP collector, etc.) are now automatically skipped with a printed reason instead of hard-failing the whole run, and a final PASS/SKIP/FAIL summary is printed. Groups whose coverage is already run by a parent task are intentionally excluded from the aggregation to avoid running the same suite twice — `test:matrix` (duplicates `db`+`hsm`), `test:ui-auth`/`test:ui-oidc` (already run by `test:ui`), and `test:spire-pki`/`test:spire-sds`/`test:spire-kmip-key-manager`/`test:spire-kmip-upstream-authority` (already run by `test:spire`/`test:spire-kmip`) — all remain available standalone by name. Added `has_cmd`, `has_env_vars`, and `docker_ready` helpers to `.mise/lib/common.sh` for reuse by this and future task scripts.
