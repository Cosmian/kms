## Bug Fixes

- Guard key rotation against concurrent re-keys of the same key: `objects` rows carry a `version` counter (new column on SQLite, PostgreSQL and MySQL, added automatically on startup; stored in the record for Redis-Findex) incremented on every write. `Re-Key`, `Re-Key Key Pair` and `Re-Certify` now commit the replacements, the retirement of the old key and the re-wrapped dependants in one atomic batch that is conditional on the version read at the start. The losing request fails with a `Conflict` error and persists nothing, instead of silently overwriting the first replacement and orphaning its new key; a replacement is never visible to clients before the rotation commits. A direct JSON-TTLV operation receives HTTP 409, a `RequestMessage` batch item receives `General Failure` with a `Conflict:` message. Auto-rotation skips a key that hit a `Conflict` and leaves it to the next scheduler check ([#1006](https://github.com/Cosmian/kms/issues/1006)).
- Persist the automatic activation and deactivation of an object with a version-consistent snapshot, so that `Re-Certify` of a certificate whose activation or deactivation date has passed no longer fails against its own state update.
- Report a `Conflict` when a conditional update targets an object deleted in the meantime on Redis-Findex, as the SQL backends already do.
