## Security

### Bug Fixes

- Remove `cookie` 0.16 (RUSTSEC-2026-0594, private-cookie nonce reuse after `fork`) from the KMS workspace dependency graph (`Cargo.lock`): `actix-session` and `actix-identity` are replaced by an in-house AES-256-GCM `auth_session` cookie for the Web UI (`HttpOnly`, `SameSite=Lax`, `Secure` under the same rule as before, 24-hour expiry now enforced by the server, key derived from `ui_session_salt`). The advisory exception is removed from `deny.toml`, `.cargo/audit.toml` and `sbom/openvex.json` ([#1480](https://github.com/Cosmian/kms/issues/1480)). **Existing Web UI sessions are invalidated once at upgrade: users log in again**. The separately shipped Auth Verifier (`authentication/` submodule, own `Cargo.lock`) is not covered by this change and still needs its own fix
- Remove the stale `cargo vet` exemptions of the crates dropped from `Cargo.lock` (`base64` 0.20.0, `cookie` 0.16.2 and 0.18.1)
- Lock `cookie` 0.18 (reqwest `cookie_store`, used by `ckms` and the server HTTP client) at the patched 0.18.3 for RUSTSEC-2026-0594

## Testing

- Cover the Web UI session cookie end to end: the OIDC `login_flow` and `callback` round trip against a mock `IdP` (sealed PKCE/state/nonce, state and nonce refusals, fresh cookie holding only the user) and the SPIFFE `login_svid` login run in the Rust test suite of both FIPS and non-FIPS builds; the Auth Verifier Playwright login checks the live `auth_session` cookie attributes, lifetime and removal at logout

## Documentation

### Tooling

- AI instructions and skills: Nix vendor hashes (`nix/expected-hashes/`) are no longer renewed in feature, fix or dependency PRs after a `Cargo.lock` or `ui/pnpm-lock.yaml` change; the nightly workflow (`nix-update-hashes.yml`) does it
