## Security

### Bug Fixes

- Remove `cookie` 0.16 (RUSTSEC-2026-0594, private-cookie nonce reuse after `fork`) from the dependency graph: `actix-session` and `actix-identity` are replaced by an in-house AES-256-GCM `auth_session` cookie for the Web UI (`HttpOnly`, `SameSite=Lax`, `Secure` under the same rule as before, 24-hour expiry now enforced by the server, key derived from `ui_session_salt`). The advisory exception is removed from `deny.toml`, `.cargo/audit.toml` and `sbom/openvex.json` ([#1480](https://github.com/Cosmian/kms/issues/1480)). **Existing Web UI sessions are invalidated once at upgrade: users log in again**
- Lock `cookie` 0.18 (reqwest `cookie_store`, used by `ckms` and the server HTTP client) at the patched 0.18.3 for RUSTSEC-2026-0594

## Documentation

### Tooling

- AI instructions and skills: Nix vendor hashes (`nix/expected-hashes/`) are no longer renewed in feature, fix or dependency PRs after a `Cargo.lock` or `ui/pnpm-lock.yaml` change; the nightly workflow (`nix-update-hashes.yml`) does it
