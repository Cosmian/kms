## CI

- Run each pull-request CI job only when files related to it changed. `.github/ci-paths.toml` lists, per CI unit (clippy, machete, no-nix, forward-proxy, the documentation build, publish dry run, XKS remote, every `test-group.yml` suite, the Windows jobs and the macOS PKI job), the regexes of the files that trigger it; the new `changes` job of `main.yml` runs `mise run dev:ci-changes` (`.mise/scripts/dev/ci_changes.py`) and passes the skipped units down as `skip-units` to `test_all.yml` and `test_windows.yml`. Any `crate/**` change still runs the whole-workspace jobs (clippy, machete, no-nix, publish dry run, `db:sqlite`, Windows `cargo test`); code linked into the server also runs `spire` and `forward-proxy`; `xks-remote` runs only on `routes/aws_xks/`, its scripts and `test_all.yml`; `cargo-clippy` is a `strict` unit: it runs only on `*.rs`, `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`, `clippy.toml` and `.cargo/config.toml` changes, and is no longer forced by the `full` list (`mise.toml`, Nix and mise-library files) or by an unmatched path, nor triggered by other `crate/` files or workflow edits. The other suites (`ui`, `interop:*`, `pki`, `pkcs11`, `obs`, `hsm`, `cloud`, `db:*` other than sqlite, and the Windows mirrors) run only on their own crates, paths and test scripts: the database suites on `server_database`, the KMIP interop suites on `kmip` and the `/kmip` route. `build-documentation` runs only on `documentation/`, `AGENTS.md`, `CONTRIBUTING.md`, the AI instruction and skill files and the docs tasks. A change to `main.yml` or `test_all.yml` runs only the units defined in or called directly by it, plus `interop:pykmip` for `test_all.yml` as the smoke leg of the suite matrix; `no-nix.yml`, `test_windows.yml`, `cargo_test.ps1`, `test-group.yml`, `ci-paths.toml` and `ci_changes.py` run no suite, so `no-nix` and the Windows `cargo test` need a Rust source change. A changed file that matches no unit and is not ignored, a file matching `full`, or an empty diff runs everything, as do tags, the nightly schedule and manual dispatch.
- Show fewer skipped rows in the pull-request run graph. `ci_changes.py` now also emits `suites-matrix` (the legs of the running suites, from the `variants` of each unit in `ci-paths.toml`) and `run-test` / `run-windows` (from its `[callers]` table). `test_all.yml` runs the `db`, `interop`, `hsm`, `obs`, `pkcs11`, `pki` and `spire` suites as legs of one `test-suites` matrix job, so a suite that does not run has no row (`test-db.yml` and `test-interop.yml` are gone, the database environment moved into `test-group.yml`, which no longer takes `skip-units` or `extra-env`); `test-cloud` and `test-ui` stay separate jobs so their secrets are scoped by the job, not by an expression. `main.yml` skips the whole `test` or `windows` call, as one row, when none of its units runs. `test_all.yml` loses its `workflow_dispatch` trigger (dispatch `main.yml`; `mise run dev:ci-changes --all` emits the full matrix for non-PR events). The nightly-only link check moved from `main.yml` to its own `linkcheck.yml` workflow, so pull requests no longer list it.
