## CI

- Run each pull-request CI job only when files related to it changed, and list no "skipped" row for the others. `.github/ci-paths.toml` describes every CI unit (clippy, machete, no-nix, forward-proxy, the documentation build, publish dry run, XKS remote, cloud, UI, every `test-group.yml` suite, the real HSMs, the macOS PKI job and the Windows jobs) by the regexes of the files that trigger it and by its legs: `variants`, `runners`, `setup`, `timeout`, `lock`, `environment`, `events`, plus the `upstream`, `no-fork-pr` and `dependabot` flags. The `changes` job of `main.yml` runs `mise run dev:ci-changes` (`.mise/scripts/dev/ci_changes.py`), which emits one output, `suites-matrix`: the legs of the units the diff triggers, filtered by event, secret availability, fork PR and Dependabot.
- Run every unit as a leg of the single `test-suites` matrix job of `test_all.yml`, through the one reusable runner `test-group.yml` (Nix, plain or Windows setup, selected per leg). `no-nix.yml`, `forward_proxy.yml`, `test_windows.yml` and the `cargo-clippy`, `cargo-machete`, `build-documentation`, `cloud`, `ui`, `xks-remote`, `interop-macos`, `test-hsm-hardware` and `cargo-publish-dry-run` jobs are gone; a PR run lists only the legs its changed files trigger, and `cargo-publish` (tags only) is the one skipped row. The `secrets:` expressions of `test-suites` scope each secret to its legs, and a leg's `lock` is its concurrency group (real HSMs, XKS server).
- Keep nightly, tag and manual runs complete: `--all --event <schedule|tag|workflow_dispatch>` never reads the diff and emits every unit whose `events` list the event (no `xks-remote` on schedule, no publish dry run on tags, real HSMs off pull requests, upstream and fork rules unchanged). `--dependabot` keeps the Rust and documentation units that already ran for Dependabot PRs.
- Make `cla.yml` a standalone `pull_request_target` / `issue_comment` workflow, so the CLA assistant works for external fork PRs.
- Run only the shared-setup probes (one leg per setup path) when a PR changes only CI wiring (`ci_setup` set of `ci-paths.toml`), pass the Google OAuth secrets to the `cloud` leg only, document that `cargo-publish` waits for the whole `test-suites` matrix, and give `cla.yml` job-level permissions and a fork check that also covers `recheck` comments.
- Fix fail-open paths of the classifier: non-ASCII file names (`git diff -z`), `pkg/kms.toml`, `.rustfmt.toml`, the `test_data` and `.github/reusable_scripts` submodules now trigger the strict units that use them. Locally, `dev:ci-changes` diffs from `origin/$GITHUB_BASE_REF` (default `origin/develop`), so every branch commit counts; CI keeps `--base HEAD^1`.
- Document the workflows in `.github/workflows/README_main.md`; `mise run dev:ci-changes --self-test` runs the classifier tests against the real config. `ci_coverage.py` counts every unit key as a CI root and ignores `description:` prose, which used to mark the umbrella `test*` tasks as covered.
