## CI

- Run each pull-request CI job only when files related to it changed. `.github/ci-paths.toml` lists, per CI unit (clippy, machete, no-nix, forward-proxy, publish dry run, XKS remote, every `test-group.yml` suite, the Windows jobs and the macOS PKI job), the regexes of the files that trigger it; the new `changes` job of `main.yml` runs `mise run dev:ci-changes` (`.mise/scripts/dev/ci_changes.py`) and passes the skipped units down as `skip-units` to `test_all.yml`, `test-db.yml`, `test-interop.yml`, `test-group.yml` and `test_windows.yml`. Any `crate/**` change still runs the whole-workspace jobs (clippy, machete, no-nix, publish dry run, `db:sqlite`, Windows `cargo test`); code linked into the server also runs `spire`, `xks-remote` and `forward-proxy`. The other suites (`ui`, `interop:*`, `pki`, `pkcs11`, `obs`, `hsm`, `cloud`, `db:*` other than sqlite, and the Windows mirrors) run only on their own crates, paths and test scripts: the database suites on `server_database`, the KMIP interop suites on `kmip` and the `/kmip` route. A change to a reusable workflow (`main.yml`, `test_all.yml`, `test-group.yml`, `test-db.yml`, `test-interop.yml`, `test_windows.yml`) runs only the units that call it directly plus one representative suite leg, not every suite; `ci-paths.toml` and `ci_changes.py` are validated by the self-test of the `changes` job. A changed file that matches no unit and is not ignored, a file matching `full`, or an empty diff runs everything, as do tags, the nightly schedule and manual dispatch.
