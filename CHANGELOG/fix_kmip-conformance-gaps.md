## Bug Fixes

### KMIP
- Return version-specific binary response tags and Result Reason values for KMIP 1.x clients, mapping lifecycle failures to `PermissionDenied` where KMIP 1.4 has no dedicated code.
- Require an exact Result Reason for every expected KMIP response failure while preserving diagnostic assertions for HTTP failures; correct precise reasons for unsupported key formats and invalid Certify object types.
- Report the KMIP 2.1 Result Reason from each operation's error table: `Wrong_Key_Lifecycle_State` for crypto-operation lifecycle failures, `Invalid_Object_Type` / `Incompatible_Cryptographic_Usage_Mask` for keys the caller may use but the operation cannot, `Object_Not_Found` for Destroy, Revoke and DeriveKey, `Invalid_Attribute_Value` for invalid key lengths, `Read_Only_Attribute` for Add/Set Attribute, `Feature_Not_Supported` for unsupported Hash/MAC algorithms or a missing HSM, and `Object_Already_Exists` for duplicate objects.
- Enforce BatchCount consistency, default omitted batch-error behavior to `Stop`, echo Client Correlation Values, and reject unsupported critical Message Extensions.
- Restrict configured Operators from lifecycle, attribute-management and administrative operations (`Get` and `Export` stay available on owned or granted objects), prevent sensitive KMIP payload logging, and reject cyclic or oversized certificate chains.
- Bound Locate offsets, avoid pre-filter limits for destroyed-only results, advertise `ReCertify`, and reject unsupported key-compression requests while accepting uncompressed EC keys.
- Attribute operations: Get Attributes with no Unique Identifier now uses the ID Placeholder (no table scan), returns all stored attributes (including CertificateType, DigitalSignatureAlgorithm, KeyValueLocation/Present, NISTKeyType, ObjectGroupMember, OpaqueDataType, PKCS12FriendlyName, ProtectionLevel/Period, UsageLimits, X.509 identifier/issuer/subject), no longer invents Lease Time, Destroy Date or Random Number Generator values, derives the Short Unique Identifier from the SHA-256 of the Unique Identifier (KMIP 2.1 §4.56), reports the Key Format Type a default Get produces (PKCS#1 for RSA, Raw for symmetric keys, §4.26 Table 81), returns rotation attributes only when requested, and rejects duplicate Attribute References. Get Attribute List returns the object's real attribute names and its Unique Identifier. RSA key generation no longer stores an implicit Cryptographic Parameters attribute.
- Add/Set/Modify/Delete Attribute: client changes to attributes the spec marks not modifiable/deletable are refused (`Read_Only_Attribute` / `Attribute_Read_Only`), Add reports `Attribute_Single_Valued`, Modify requires an existing attribute and honours the new `Current Attribute` field, Delete of a missing attribute or instance fails with `Attribute_Not_Found` / `Attribute_Instance_Not_Found` and accepts a Link reference, Modify/Delete/Set update Last Change Date, Set Name replaces its single instance (`Multi_Valued_Attribute` otherwise), Set Activation Date requires Pre-Active, and KMIP 1.4 Add Attribute echoes the added attribute. `NISTKeyType` and `PKCS12FriendlyName` use their spec tag names inside New/Current Attribute.
- PKCS#11 operation: Function codes follow the `CK_FUNCTION_LIST_3_0` offsets required by KMIP 2.1 §11.38 (e.g. `C_Finalize` = 2), the full function list is recognised (unimplemented functions answer `CKR_FUNCTION_NOT_SUPPORTED`), the Function is required (`Invalid_Field`), the PKCS#11 Interface is modelled (`PKCS_11_Invalid_Interface` for non-default interfaces), a missing HSM returns `Feature_Not_Supported`, and `PKCS11` is advertised by Query only when an HSM and a Crypto Officer are configured.
- Locate returns objects newest first (descending Initial Date, merged across stores); KMIP 1.4 Locate decodes the Storage Status Mask as an Integer bit mask (combined masks such as on-line + archival no longer fail), and KMIP 1.4 Get honours Key Wrap Type.
- Export of a Destroyed object succeeds without key material (Get still fails with `Object_Destroyed`); Get of a Deactivated object reports `Permission_Denied`.
- Query: models Object Groups (`Feature_Not_Supported`), requires a Query Function, answers Query Extension List/Map with the `CertificateAttributes` extension and returns Server Information to KMIP 1.4 clients as an empty (vendor-specific) structure, since its standardized fields only exist from KMIP 2.0. Check evaluates Usage Limits Count (`Usage_Limit_Exceeded`) and rejects Lease Time (`Feature_Not_Supported`). Log writes its message to the server log and requires it. Interop accepts the Reset function. The JSON and binary `/kmip` endpoints process every minor version of KMIP 1 and 2 (same major, different minor, KMIP 1.4 §11.1) and reject other majors with `Unsupported_Protocol_Version`.
- Object creation operations: Create Key Pair resolves Cryptographic Algorithm, Length and Domain Parameters (curve) from the Private/Public Key Attributes as well as the Common Attributes and rejects values that differ between the two keys (`Invalid_Attribute`) instead of silently generating the default curve; Create/Register reject Cryptographic Domain Parameters on symmetric keys and secret data (`Invalid_Attribute`), Create of an unsupported object type returns `Invalid_Object_Type`, Register sets the Initial Date to the current time and returns `Feature_Not_Supported` for unsupported object types, Import keeps a client-supplied State, rejects an Object Type that does not match the object and returns `Invalid_Field` for reserved Unique Identifiers.
- Derive Key requires an Active base object (`Wrong_Key_Lifecycle_State`) and returns `Feature_Not_Supported` for unsupported derivation methods, `Invalid_Object_Type` for a wrong base object type and `Incompatible_Cryptographic_Usage_Mask` for asymmetric key-agreement masks; the KMIP 1.4 Derive Key request carries its required Object Type.
- Create Split Key rejects Protection Storage Masks, Prime Field Size and a mismatching Object Type, applies the requested attributes to the shares, returns `Item_Not_Found` for a missing source key, `Invalid_Object_Type` for an unsupported source and `Feature_Not_Supported` when no Unique Identifier is given. Join Split Key rejects Protection Storage Masks, applies every requested attribute and returns `Invalid_Object_Type` for a share that is not a Split Key. The KMIP 1.4 Register request uses the Table 169 field order.
- Revoke and Destroy follow the KMIP 2.1 §4.57 state transitions only: Revoke checks permission before any state (no existence/state oracle), a compromise of a Destroyed object yields Destroyed Compromised, other invalid revocations return `Wrong_Key_Lifecycle_State`, Compromise Date is set (Compromise Occurrence Date defaults to Initial Date and is rejected with `Invalid_Field` for non-compromise reasons), the Deactivation Date is no longer overwritten on a compromise, and Certificate Requests return `Invalid_Object_Type`. Destroy refuses every Active object, returns `Object_Destroyed` for an already destroyed object and sets the Destroy Date.
- Re-key / Re-key Key Pair / Re-certify: an old object that is not Active keeps its state and Deactivation Date (an Active one is retired via its Deactivation Date), replacement dates are copied or shifted per Tables 298/303, Revocation Reason is not copied, Usage Limits Count is reset, request Attributes are applied, state refusals use `Permission_Denied` (checked after permission) and crypto-parameter changes `Invalid_Field`; Offset is encoded as an Interval, KMIP 1.4 Re-certify carries Offset, Re-certify honours the Certificate Request (value or new Certificate Request Unique Identifier) and returns `Invalid_Object_Type` for non-certificates; HSM Re-key rejects Offset/Attributes with `Feature_Not_Supported`.
- Certify starts objects Pre-Active unless the request's Activation Date has passed, accepts a managed Certificate Request by Unique Identifier and requires the Certificate Request Type with a request (`Invalid_Field`). Validate reports an invalid, expired, revoked or destroyed chain as a successful response with Validity Indicator `Invalid`, and returns `Invalid_Field` / `Invalid_Object_Type` for an empty chain or a non-certificate.
- Enumeration and tag codes follow the specs: KMIP 1.4 Recommended Curve (SECP256K1 = `0x19`, Brainpool from `0x37`; 1.4 curve requests previously selected the wrong curve), KMIP 1.4 Key Compression Type, KMIP 2.1 Usage Limits Unit (Byte = 1, Object = 2; persisted `Block`/`Operation` still read as `Object`), Validation Authority Type, NIST Key Type (19 values; persisted `AESP1` … `HMACSHA512` still read as the spec value with the same code, 0x1–0xF), Key Value Location Type (persisted `OnPremise` still reads as `URI`; `Unspecified`, `OffPremise` and `OnPremiseOffPremise`, which have no spec equivalent, as `UninterpretedTextString`), Client Registration Method, SECT113R2, KMIP 1.4 SHA3-RSA signature algorithms (ECDSA-SHA384/512 no longer collapse to SHA256) and PKCS#12 links; spec names for Shredding Algorithm, Unwrap Mode, Alternative Name Type, Profile Name, McEliece and MGF1 (old names still accepted); ten missing KMIP 2.1 tags added. ML-KEM/ML-DSA/SLH-DSA keep codes `0x39`–`0x4A`, which KMIP 3.0 assigns to them.
- Message semantics: Undo really reverts the earlier items (created objects deleted, modified objects restored, one transaction per item) and reports `Operation Undone` only for reverted items; an item whose objects changed since it ran, or that the server cannot revert (tag, keyset or HSM handles, re-key of a wrapping key, Covercrypt, Create/Join Split Key, Destroy with remove), keeps `Success`; Undo batches are limited to 1,000 items (`Server_Limit_Exceeded`); Maximum Response Size bounds the whole encoded response, failed items and KMIP 1.x encoding included; an operation the server does not implement (KMIP 2.1 or 1.x, e.g. Poll, Notify) fails only its own item with `Operation_Not_Supported`; undefined tags and enumeration values return `Unknown_Tag` / `Unknown_Enumeration`; a binary message without Protocol Version gets an `Invalid_Message` response instead of no answer; JSON version errors echo the request version; a failed Check empties the ID Placeholder; KMIP 1.4 Re-key, Re-key Key Pair, Check, Delete Attribute and Destroy accept an omitted Unique Identifier (ID Placeholder); KMIP 1.4 Locate returns Located Items (1.3+).
- Wire encoding: the Message Extension's Vendor Extension is a Structure whose vendor tags (`0x54xxxx`) decode, the Hashed Password Timestamp is a Date Time Extended, the Hashed Password is a Byte String, and the binary decoder rejects wrong fixed lengths, misaligned Structures and Booleans other than 0/1. Requests carrying a Hashed Password credential are refused with `Feature_Not_Supported`: the server holds no client password, so it cannot return the required Server Hashed Password. A missing Unique Batch Item ID in a multi-item batch is tolerated (it is a client requirement).
- Multi-part (Init Indicator / Correlation Value / Final Indicator) Encrypt, Decrypt, Hash, MAC, MAC Verify, Sign and Signature Verify keep their state server-side under a random Correlation Value bound to the user, operation and key, bounded in number (1024, 64 per user), expired after 5 idle minutes or one hour in total, and aborted when the key is destroyed or revoked as compromised; each Encrypt/Decrypt part returns its own output (CS-BC-M-GCM-3-21), multi-part Hash/MAC no longer chain digests, unknown values return `Invalid_Correlation_Value`, Init + Final without a Correlation Value is single-part, later Encrypt/Decrypt parts that change the Cryptographic Parameters, IV or AAD return `Invalid_Field`, and HSM keys, XTS/key-wrap/GCM-SIV/pure ChaCha20 and PGP keys return `Feature_Not_Supported` for multi-part. Multi-part AEAD Decrypt returns each part's plaintext before the final part verifies the tag (required by CS-BC-M-GCM-3-21): that plaintext is unauthenticated until the final part succeeds.
- Crypto reasons: unsupported algorithms, modes and paddings return `Unsupported_Cryptographic_Parameters` (was `Operation_Not_Supported`); a missing Decrypt IV returns `Missing_Initialization_Vector` and a wrong IV length `Invalid_Field`; an invalid Tag Length `Bad_Cryptographic_Parameters`; RNG failures `Cryptographic_Failure`; a negative RNG Retrieve Data Length `Invalid_Field`; single-part Hash/MAC without Data `Invalid_Field`. IV Length and Random IV = false are honoured, Fixed Field / Invocation Field / Counter Length / Initial Counter Value are rejected as unsupported.
- MAC and MAC Verify enforce the `MACGenerate` / `MACVerify` usage mask (`Incompatible_Cryptographic_Usage_Mask`), accept the HMAC algorithm from the request Cryptographic Algorithm and compare MACs in constant time; HMAC/SHA-3 keys created by `symmetric_key_create_request` now get these mask bits, and HMAC-SHA3 keys (`HMACSHA3224`–`HMACSHA3512`) can be created. Existing HMAC keys without them must have their usage mask updated.
- `RequestMessageHeader::default()` no longer sets a 1 MiB Maximum Response Size: now that the server enforces the limit on every operation, the old default made large client batches fail with `Response_Too_Large`.
- Types: MAC Verify gains Correlation Value / Init / Final and an optional Validity Indicator; KMIP 1.4 Encrypt, Decrypt and MAC accept an omitted Unique Identifier, and 1.4 Sign, Signature Verify, MAC Verify and Hash carry the multi-part fields.
- Sign with an RSA key and a non-RSA Digital Signature Algorithm (e.g. ECDSA) returns `Unsupported_Cryptographic_Parameters` instead of `Cryptographic_Failure`.
- Export returns all of the object's attributes as Get Attributes reports them (KMIP 2.1 §6.1.18, taken before the object is served, tags included); Register sets the Digest (SHA-256 in the default Key Format Type, plus the registered format when different, §4.21) and Fresh true unless the client sends false (§4.24); Get Attributes reports PKCS#1 for unwrapped RSA keys stored as PKCS#8.
- Register accepts an object without its Key Value (Key Value Present false, Key Value Location kept; Get and Export of it return the object as registered, a conversion or wrap request fails with `Key_Value_Not_Present`, Encrypt and MAC refuse it).
- Derive Key supports the HASH and HMAC derivation methods outside FIPS mode (KMIP 2.1 §7.12; FIPS builds return `Feature_Not_Supported`, a bare digest or HMAC is not an approved KDF).
- KMIP Login issues a ticket bound to the transport-authenticated user, Logout revokes it, a Ticket credential of another user is refused with `Invalid Ticket`; Set Constraints / Get Constraints keep a server-wide constraint set that Create, Register, Import and the other object-creating operations enforce (`Constraint_Violation`).
- The JSON TTLV encoding writes a Date-Time in whole seconds, as the binary and XML encodings do; a sub-second Initial Date is kept only for ordering Locate results.

### Security
- Bound Locate for users who are not HSM administrators: the HSM keys granted to the user are resolved first and only those are looked up, within the requested page, instead of enumerating every HSM key.
- Decrypt rejects AEAD tags shorter than 12 bytes (GCM, ChaCha20-Poly1305; OpenSSL accepted 1-byte tags) or differing from the request's Tag Length (`Invalid_Field`), single-part and multi-part.
- Bulk Encrypt of several items no longer reuses a client-supplied IV for every item (`Invalid_Field`); IV Length is bounded to 1024 bits before allocation and a server-generated GCM IV is at least 96 bits (`Bad_Cryptographic_Parameters`).
- Multi-part Sign and Signature Verify buffers are capped at 16 MiB per operation, 64 MiB per user and 256 MiB in total (`Server_Limit_Exceeded`); malformed Correlation Values are rejected before locking and expired state is freed outside the lock.
- Cap the memory held by socket-server requests in flight with a process-wide 256 MiB budget, reserved before each body is allocated.
- Re-key Key Pair requires the `Rekey` permission on the public key named by the private key's Public Key Link (`Object_Not_Found` otherwise), and Re-certify resolves the subject and issuer as the requester instead of the certificate owner (COSMIAN-2026-044, COSMIAN-2026-045).
- Batch Undo snapshots and restores only objects the requester may change, and only when they are still as the item left it (COSMIAN-2026-046, pre-release).
- Set/Add/Modify/Delete Attribute of Usage Limits, Cryptographic Usage Mask, Activation/Deactivation Date, Link, Rotate Interval and Revocation Reason require ownership or an explicit grant of the edit operation; a `Get` grant is no longer enough. Delete Attribute cannot remove server-owned KMIP 1.x (`y-`) custom attributes.

- Once `Extractable` has been set to false (server-managed `NeverExtractable` latched), Set/Modify Attribute can no longer set it back to true.
- Wrap checks the caller's permission on the wrapping key before its state, so a foreign key's lifecycle state is not revealed; the refusal is `Permission_Denied`.
- Login/Logout ticket redemption no longer scans the whole ticket store per Ticket credential (a request with many Ticket credentials could stall every ticket user); expired tickets are purged when the next ticket is issued.
- AWS and Azure BYOK export wrap a private key as PKCS#8 (as both clouds require), whatever format the KMS stores it in; wrapping with No Encoding otherwise keeps the stored format.

## Behavior changes

- `IV Length` in Cryptographic Parameters is interpreted in bits (KMIP spec). Clients that send bytes (for example the
  `ovh/kmip-go` `AES_GCM` preset, `IVLength: 12`) now get `Bad_Cryptographic_Parameters`; send `96` instead.
- `GetAttributeList` lists only attributes set on the object.
- `DeleteAttribute` of a Link with an empty identifier removes every link of that Link Type (used by the Web UI).

## Documentation

- New page `kmip_support/_login.md`: Login and Logout behaviour, examples taken from the `negative/security/ticket_*` vectors, and a security review.
- `update_readme_kmip.py` now reads KMIP 2.x operation headings (`<h3>`, previously it silently fell back to a hard-coded table), matches them exactly and fails when none is found; it generates the Login, Logout, Delegated Login, Get/Set Constraints rows, the Login and constraints section and the Key Value Present note that were edited by hand in `support.md`. ## Testing

- The OASIS XML vector harness (`ckms` test suite, non-FIPS) now runs every vector of `kmip/v1.0`, `v1.3`, `v1.4`, `v2.0` and `v2.1` (the two PKCS11 vectors against a SoftHSM2 token, in `mise run test:hsm:softhsm2 --variant non-fips`) and the published KMIP Test Cases notes (cn01), asserts that KMIP 3.0 requests are rejected, and accounts for every other file under `kmip/website` as a mirror of a `v*/XML` vector, a draft-stage file (not run) or a non-vector. Response header, operation, batch item ID, decrypted data, key bytes, key format type, Query lists, attribute lists and attributes are compared; Locate and Sign results are no longer copied into the expectation. Every tolerance is listed in `tests/xml/deviations.rs`: per-vector `DEVIATIONS` and `KNOWN_FAILING` (a listed vector that passes, or fails for another reason, fails the suite), the systematic lists (unimplemented attributes, unsupported Query operations and object types, the 1.x "Key Format Type" name), and the rule that server-generated objects are compared by presence and length for key bytes, digest, original creation date and Random Number Generator.
- `test_data/vectors/negative/robustness` (raw-HTTP and malformed-TTLV cases, via the new `RawHttp` step and `assert_http_status`) and `negative/security` (cross-tenant, key-output, Extractable latch and wrapping-key vectors); the `cert_roles` server config makes `owner.client@acme.com` a Crypto Officer and a new `cert_constraints` config backs the constraint vectors.
- `login.rs` unit tests cover expired tickets without sleeping: an expired ticket is refused with `Invalid Ticket` even with requests left, an exhausted ticket becomes `Invalid Ticket` when its lease ends, expired tickets free the global and per-user quota, and the default and capped lease are checked.
